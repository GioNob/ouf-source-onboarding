# Finite HUMAN profiling recovery — candidate, not deployed

This delta reuses the V35 readiness session model for an immutable file's existing profiling job. The original job, idempotency key, cumulative attempts and all quarantine evidence remain. V36 is additive: generation/version fields, immutable budget snapshots and append-only transition events. The migration grants no budget and queues no retained work. It must be installed only through a new governed schema/deployment plan; none of the consumed diagnostic APPLY procedures may install it.

The native HUMAN owner card requires file.profile and proven tenant/subject ownership. Budget/resume/cancel require file.profile plus quarantine.release and a stateless authenticated write proof. No MCP budget-grant operation is introduced. A new managed-profile-recovery.v1 session allows at most3 additional attempts in900seconds from issue, reason/actor/decisionRef and prior_job snapshot retained. Granting only advances generation/version and retains FAILED; a separate explicit HUMAN resume queues that same job and releases its retained quarantine atomically. Identical command keys reconcile a lost response without extending the session. Changed intent and stale cards conflict. Unknown outcomes, rejected quarantine, changed custody/input and ambiguous multiple-job history require reconciliation.

Each claim reserves a cumulative attempt and fresh generation. Completion/failure requires the exact generation, worker, live lease, input binding and finite session deadline. Profile and job completion commit in one transaction. An old worker with the same configured name cannot publish after reclaim/cancel. Cancellation fences running work and leaves all counters and evidence. No database transaction or shared lock is retained across remote reads/backoff. One live read across the owner bounds recovery pressure; only32 due rows are inspected per poll.

The versioned initial managed-profile-initial.v1 profile retains maximum5 attempts and bounds elapsed time to900seconds from original admission, including queue and attempt duration. This intentionally narrower interactive10MiB profile avoids day-long jobs while requiring explicit HUMAN recovery; it does not silently adopt old in-flight jobs without input-binding evidence. Default progressive waits5/15/60/300/900seconds have20% jitter. Valid Retry-After is never shortened; beyond the remaining budget stops. HTTP429/502/503/504 and typed connect/timeouts are the read-only transient classes. Permanent/unknown/TLS/DNS/input/custody failures stop. The Gateway read transport disables automatic retries and redirects, bounds connection/pool/read waits, limits bytes and enforces a monotonic body deadline; worker lease/deadline fences late results. Native DNS/nft and slow-server qualification remain required on the deployment path. Apache transport API: https://hc.apache.org/httpcomponents-client-5.6.x/5.6.5/httpclient5/apidocs/org/apache/hc/client5/http/impl/classic/HttpClientBuilder.html .

Real PostgreSQL qualification covers original FAILED5 through a new session, cumulative6–8, explicit second session, lost-response reconciliation, concurrent commands, stale/late worker, cancellation, Retry-After/jitter, old elapsed budget, ownership and immutable history. Separate35→36 upgrade qualification must preserve the full legacy failed row, quarantine, asset and all35 migration history entries. Existing V34→35 upgrade test remains explicitly pinned35 so the added migration cannot weaken its assertion.

Source qualification is not deployment, a HUMAN runtime decision, effective permission evidence, new upload/acquisition, merge or E2E/release acceptance. Farmacie on target remains FAILED5. Broader dependency incident correlation, admission/capacity/retention metrics, alerts, full cross-module cohort and target fault/two-client evidence remain separate unclosed resilience/M2 gates.
