# Authorization R1b — PET 1.5

Normative mapping: §§109.1–109.4 administration and local SDK; §109.6 freshness; §7.2 explicit DENY; §36.10 data labels; §34.2 resource scope/detail; §109.14 negative tests.

The admin API is `/api/trusted-human/v1/authorization`, specified in `openapi/authorization-admin-v1.yaml`. `authorization.policy.admin` is a platform administration privilege, not a tenant self-service privilege. Every route requires a validated canonical HUMAN principal and local policy authorization. Mutations additionally require trusted middleware to set `ouf.csrfValidated=true` after validation. Supplying headers cannot set this server attribute. Missing binding denies access. Production IAM/THS integration and its acceptance evidence remain the external R4 gate.

Register immutable owner/capability semantics, create a draft based on the current ACTIVE reference, edit policy or individual grants with quoted `If-Match`, and publish a new immutable monotonic version. Stale draft revisions return 412; missing ETag 428; a changed ACTIVE reference or immutable descriptor conflict returns 409. DELETE abandons a draft or removes a draft grant; revocation becomes effective when the new bundle is published and each consumer refreshes. Create a new draft to rebase; historical bundles and append-only audit are retained. Publication serializes on the same database advisory lock as the existing registry activation.

SDK 1.1 adds optional role/resource/DAL/detail/assurance constraints without changing existing constructor signatures. Missing constrained claims deny; no directory/network lookup occurs during evaluation. Explicit matching DENY overrides every ALLOW. A decision returns its exact bundle reference, permitted detail and resource scope. Consumers must bind resource attributes from authoritative owner metadata and enforce the decision before releasing that detail; client arguments are not trusted resource labels.

`ouf.authorization.registry-url` enables authenticated background HTTPS refresh; `ouf.authorization.registry-token-file` points to a workload token file. Interval defaults to 30 seconds and must be below `ouf.authorization.max-staleness-seconds` (default 300). Responses have bounded size, five-second whole-response deadline, SHA-256 content verification, strict known fields and immutable identity/version validation. An invalid refresh retains the last valid snapshot only within max staleness. At expiry protected requests fail closed. The startup pinned-file configuration remains supported. Rollbacks are republished as a new higher version; changing lineage requires explicit bootstrap/restart.

`AuthorizationAdminRuntimeTest`, SDK conformance vectors and cache tests provide deterministic lab evidence. They do not certify a real IdP, browser CSRF flow or production role directory. Each module's owner-specific DAL and OA projection remains responsible for output minimization.

## R2f review browser

`/trusted-human/r2f?kind=geometry|property&id=<uuid>` is physically served by Onboarding and requires a verified human with `resolution.issue.read`. Its same-origin requests go through Gateway to the UDP-owned review and decision endpoints. The shell does not receive or store bearer tokens. It renders an EPSG:4326 geometry overlay, source provenance, scalar candidates and an explicit choice with a reason. UDP issues a synchronizer token bound to the verified subject and tenant, backed by a Secure/HttpOnly/SameSite=Strict session cookie; commands require that token and enforce the configured `ouf.ths.origin`. TLS, sticky/distributed sessions and the actual IdP-to-Gateway browser-session adapter remain deployment prerequisites under the existing R4 IAM gate. No frontend identity claim is trusted.

`tests/browser/r2f-review.test.cjs` tests rendering and command requests with explicit API fixtures. UDP runtime tests separately test owner authorization, immutable decisions and stale evidence. A green browser fixture is not production IAM acceptance.
