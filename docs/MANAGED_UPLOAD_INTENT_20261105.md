# Durable managed-file upload candidate

Prepared against exact source-lock candidate `73498c17596ae155a3ed9ab36acfd6bb69da9846` for [deploy PR54](https://github.com/GioNob/ouf-deploy/pull/54). No deployment or source-lock promotion is performed by this change.

V39 persists the owner, request identity, expected SHA256/size, fixed object reference and storage epoch **before** PUT. The owner commits the reservation, performs S3 I/O without a database transaction, then atomically registers the asset, delegated receipt and ACK under the same ACTIVE epoch. Existing completed V31 receipts remain readable. The transport disables connection retries and has a 60-second call deadline.

An intent permits one dispatch. A retry can read the ACK or reconcile the reserved object's exact bytes. Missing objects, denied reads, mismatched bytes and ambiguous failures never cause another PUT. Reconciliation has a durable maximum of 128 reads within 24 hours; there is no automatic scheduler or implicit renewal. A crash between reservation and PUT conservatively leaves an unresolved intent requiring intervention. No operation deletes its history or resets that budget.

Both HTTP upload paths retain their authentication, tenant, checksum and size checks. Direct upload accepts an optional `Idempotency-Key` header, bounded to the same 128-character syntax as delegated upload. With no key each request remains a distinct upload; retry deduplication across such requests is not claimed. Direct and delegated identities have separate namespaces. Responses retain their existing shapes and object references.

The owner-local control row rejects new dispatches and ACKs outside ACTIVE or after an epoch change. Generation and phase cannot regress. This does **not** stop a PUT already in flight or prove that old deployed processes/other services have stopped writing. Production rollout therefore still requires coordinated writer drain/stop, storage credential fencing, fresh generation binding and operator reconciliation. No public operator endpoint, HUMAN authority, recovery budget grant or target configuration is added here.

Qualification uses the actual Java owner and Flyway migrations with PostgreSQL 17.11 and the exact OCI33 SeaweedFS artifact previously qualified in deploy PR54. The dedicated workflow checks real process termination before/after PUT, lost application response, concurrent retry, stale ACK, drain/freeze, wrong bytes, durable read budgets and immutable bindings. A thrown lost-response fixture is distinguished from a wire-level proxy fault; no claim is made about all transport failures. Results must be read from the exact successful run and its preserved checksummed artifact. Native workflow completion is separate from the full module CI and from production acceptance.
